Phase 13 — data layer rework. Read AGENTS.md (updated: per-parent pages, profile photos, new ArtifactStore layout, write-failure rule). Data + minimal UI adapters only; phases 14–15 redo the UI.

Bugs found in the deployed artifact (fix them, add tests that reproduce them first):
- A single rejected db write (likely a month doc over 256 KB because pages with drawings/photos were stored inside one month document) set `canWrite = false` forever, so every later write — including 설정 › 아이 › 기본 페이지 색 (조비안 → yellow) — was silently dropped and the UI reverted. Apply the AGENTS.md rule: keep pending edits, show a retry banner state (`store.syncState: 'ok' | 'saving' | 'retrying' | 'error'` + human message), auto-retry with backoff, only revoked/not_granted disable writing.
- Child default color: pages without an explicit `color` must follow `child.pageColor` immediately when it changes.

Model changes (AGENTS.md data model):
1. Page id `${date}__${childId}__${authorId}`, single `text` field (no notes array), optional `color`. Migration from the current shapes (month docs with `pages` maps of notes, and older `entries`): split each old page into one page per note author (that author's notes joined by blank lines); the drawing/photos/tags go to the page of the earliest note author (or 'dad' if no notes); comments/reactions attach to that same page. Keep migration idempotent, mark done, never delete source data until the new docs are confirmed written.
2. Child.photo + Child.photoHistory: `setChildPhoto(childId, blob)` uploads (assets / data URL in LocalStore / Supabase Storage) and pushes the previous photo into history; `useHistoryPhoto(childId, photoId)`; `deleteHistoryPhoto(childId, photoId)` (also deletes the asset when possible). History never auto-prunes.
3. ArtifactStore layout per AGENTS.md: `meta/config`, `index/<YYYY-MM>`, `pages/<pageId>`. Subscribe to meta + index docs (small); load `pages/<id>` on demand (getPage async-capable: expose `loadPage(id): Promise<Page>` plus a cache) and prefetch the current month. Enforce the 200 KB page budget before writing (stroke simplification at 0.5 px first, then a clear error "그림이 너무 커서 저장할 수 없어요. 일부를 지워 주세요").
4. LocalStore: same model; keep localStorage but move photos to IndexedDB (data URLs in localStorage blow its 5 MB quota) with a tiny wrapper; try/catch everywhere.
5. SupabaseStore + `supabase/migrations/004_author_pages.sql`: pages keyed by (date, child_id, author_id), child photos table or jsonb on children, Storage for profile photos; keep RLS consistent (each writer edits only own pages? — no: both spouses may edit any page, but author_id is fixed at creation).
6. Backup format v3 (`lib/exportFormat.ts`): JSON with pages including drawing; a function `toDatedArchive(snapshot)` → list of files `diary/YYYY/MM/DD/<child>-<author>.json` and `diary/YYYY/MM/DD.md` (all pages of that day, readable), so backups accumulate per date. Keep v1/v2 import.
7. Tests: the color-follow bug, write failure does not disable writing, migration split by author, 200 KB budget, photo history keep/delete, dated archive paths.
